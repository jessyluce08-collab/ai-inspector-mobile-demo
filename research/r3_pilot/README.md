No study is authorized by this patch. The existing three public HTML files remain unchanged. Default build is a technical-only preview; no pilot launch occurs on merge. The new consent/export variant preserves all scientific inputs, trial DOM, CSS, ordering and geometry algorithms.

From repository root, using the existing Python environment and its existing jsonschema dependency:

```
python research/r3_pilot/tools/build_pilot.py
python research/r3_pilot/tools/freeze_lock.py
python -m unittest discover -s research/r3_pilot/tests -p 'test_*.py' -v
python research/r3_pilot/tools/analyze.py /path/to/technical-result.json --purpose technical --output /private/reports/technical
```

No participant runtime dependencies or network calls are introduced. Original raw JSON is never overwritten. Exit0means processing completed, not that a pilot was qualified;2means invalid/conflicting inputs were reported;1means configuration or admission refused. Read every ledger row. Input files are limited to2MiB and500per invocation as software resource limits, not scientific criteria. Reports are private, not artifacts to publish on Pages.

Synthetic fixtures and their explicit catalog are generated by the test fixture factory; no participant observations are used. Use `--purpose synthetic --catalog research/r3_pilot/fixtures/SYNTHETIC_CATALOG.json` with its listed files. The report is labelled synthetic and never admitted as human data. Technical diagnostics are explicitly rejected as response files.

The final lock records exact pilot HTML/build/code, manifest and analysis/doc/schema hashes; preserve it alongside the actual deployed bytes. Publish only the new immutable pilot HTML directory after authorization, never private configuration/register/results. Participant-visible contact/retention/review descriptions are intentionally embedded; choose information suitable to disclose, never credentials or sensitive storage access details.

Each admission-register participant entry has participant_id (PILOT- suffix4–18letters/digits/hyphens), eligible (true/false), withdrawn (true/false), consent_version (R3-PILOT-CONSENT-1), consent_documented_at (actual offset-aware ISO timestamp). Entries are pseudonymous. The register root purpose=PILOT_ADMISSION, protocol_version=R3-FEASIBILITY-PROTOCOL-1 and authorization_file_sha256 equals the approved configuration bytes. An empty template permits no pilot admission. Keep the separate enrollment/return count for files never received; exports cannot provide that denominator.

Validation-only projection is internal: after strict pilot schema/build checks, frozen legacy structural checks are reused on an in-memory copy. It does not change raw files, grant consent or reclassify technical data. Pilot intake always refuses technical records first. Display flags are not physical calibration; no detector or statistical inference is performed.
